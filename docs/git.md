# Git 連携

ルートディレクトリが Git で管理されているとき、左ペインの「Git」タブから変更の確認・コミット・ブランチ操作・履歴の表示・リモートリポジトリの表示とやり取り（フェッチ・プル・プッシュ）・マージ・チェリーピックができる。

## 1. 基本方針

1. **PC にインストール済みの `git` を使う**  
   Git の処理をアプリに組み込まず、`git` コマンドを子プロセスとして実行する（AI ツールと同じ考え方）。ユーザーの `.gitconfig`、認証（Git Credential Manager など）、フック、署名の設定がそのまま効く。必要な Git のバージョンは 2.30 以降。
2. **リポジトリの中にアプリ用のファイルを作らない**  
   アプリの状態（コミットメッセージの下書きなど）は `%LOCALAPPDATA%` に置く。`.git` の中もアプリ独自のものは書かない（`git` コマンドが書くものを除く）。
3. **通信はユーザーの操作でだけ行う**  
   フェッチ・プル・プッシュはボタンやコマンドで実行したときだけ通信する。自動フェッチは既定で無効（設定で有効にできる）。オフラインでも、通信しない操作はすべて使える。
4. **取り消せない操作は確認する**  
   変更の破棄、ブランチの削除、強制プッシュなどは実行前に確認ダイアログを出す。

## 2. 対象のリポジトリ

| 状況 | 対象 |
| --- | --- |
| ルートディレクトリがリポジトリの中にある | そのリポジトリ（`git rev-parse --show-toplevel`）。リポジトリの最上位がルートディレクトリより上にあってもよい。その場合、変更一覧はルートディレクトリの外のファイルも含めて表示し、外のファイルは「ルート外」と分かるようにする |
| ルートディレクトリの下に複数のリポジトリがある | 探索で見つけた `.git` を持つフォルダを一覧にし、Git タブの上部で切り替える。既定は開いているファイルを含むリポジトリ |
| どちらでもない | Git タブに「Git リポジトリではありません」と表示し、「リポジトリを作成」（`git init`）ボタンを出す |
| `git` が見つからない | Git タブに案内（Git for Windows の入手先）を表示する。ほかの機能には影響しない |

- サブモジュールは独立したリポジトリとして一覧に出す（親リポジトリ側では、サブモジュールの変更は 1 行として表示する）。
- ベアリポジトリ、`git worktree` で作った作業ツリーも、作業ツリーとして開いていれば通常どおり扱う。

## 3. 画面

### 3.1 Git タブ（左ペイン）

左ペインの切り替えに「Git」を加え、「ファイル」「検索」「アウトライン」「Git」の 4 つにする。`Ctrl+Shift+G` で Git タブを表示する。リポジトリがあるとき、タブの見出しに変更のあるファイルの数を表示する。

Git タブの中は上から次の順に並べる。各セクションは折りたためる。

```text
┌ ファイル 検索 アウトライン Git(3) ┐
│ [repo: mark-shell ▼]               │ ← 複数リポジトリのときだけ
│  main ↑1 ↓2      [⟳][↓][↑][…]     │ ← ブランチ、先行/遅れ、フェッチ・プル・プッシュ
├────────────────────────────────────┤
│ ┌ コミットメッセージ ────────────┐ │
│ │                                │ │
│ └────────────────────────────────┘ │
│ [コミット ▼]                       │ ← ▼: 修正コミット / コミットしてプッシュ
├────────────────────────────────────┤
│ ▼ ステージ済み (1)            [−]  │
│     M  docs/git.md                 │
│ ▼ 変更 (2)               [↶][+]    │
│     M  README.md                   │
│     D  old.md                      │
│ ▼ 未追跡 (1)                  [+]  │
│     U  memo.md                     │
│ ▶ 競合 (0)                         │ ← マージ中だけ表示
├────────────────────────────────────┤
│ ▼ 履歴                 [main ▼]    │
│  ● 仕様書を更新           3 分前   │
│  ● ターミナルの一覧を…    昨日     │
│  ┊                                 │
├────────────────────────────────────┤
│ ▶ ブランチ                         │
│ ▶ リモート                         │ ← リモートごとのブランチと未取り込みのコミット
│ ▶ スタッシュ                       │
└────────────────────────────────────┘
```

### 3.2 差分タブ（右ペイン）

差分は右ペインのタブとして開く（ファイルのタブと同じ並びに置く。仮タブ・固定タブの扱いもファイルと同じ）。

- タブ名は `README.md (作業ツリー)`、`README.md (ステージ)`、`README.md @ 9c3ccd2` のようにする。
- 表示モード: 「左右」（変更前と変更後を並べる）と「行内」（1 列に削除行と追加行を並べる）を切り替える。既定は左右。
- 行の中の変わった部分（単語単位）を強調する。
- 変更のない部分は折りたたみ、前後 3 行だけ表示する。クリックで広げる。
- 作業ツリーの差分では、変更後の側を直接編集できる（エディタと同じ CodeMirror を使い、保存も同じ）。
- 差分のまとまり（ハンク）ごとに「ステージ」「ステージを外す」「破棄」のボタンを出す。行を選んでその行だけステージすることもできる。
- Markdown のファイルでは「プレビュー」に切り替えると、変更前と変更後の描画結果を並べ、変わった段落に印を付ける。
- 名前変更（`R`）は変更前後のパスを両方表示する。バイナリのファイルは「バイナリファイルが変更されました」とサイズの変化だけを表示する。画像は変更前後を並べて表示する。
- `Alt+F5` / `Alt+Shift+F5` で次・前の変更に移る。

### 3.3 そのほかの表示

| 場所 | 表示 |
| --- | --- |
| ファイルツリー | 変更のあるファイルの名前に色と記号（`M` 変更、`A` 追加、`D` 削除、`U` 未追跡、`!` 競合）を付ける。中に変更のあるフォルダには点を付ける。`.gitignore` の対象は薄く表示する（表示はする。[functional-spec.md](functional-spec.md) §2.3） |
| エディタ | 行番号の横に、ステージの内容（ステージしていなければ HEAD と同じ）からの変更を色の帯で示す（追加・変更・削除）。帯をクリックすると「変更を表示」「この変更を元に戻す」「この変更をステージ」を出す |
| ステータスバー | 現在のブランチ名と先行 / 遅れの数。クリックでブランチの切り替えを開く |
| タブの右クリック | 「変更を表示」（作業ツリーの差分）、「このファイルの履歴」 |
| ファイルツリーの右クリック | 「変更を表示」「このファイルの履歴」「変更を破棄」「ステージ」「.gitignore に追加」 |

## 4. 操作

### 4.1 変更とステージ

| 操作 | 仕様 |
| --- | --- |
| 変更の一覧 | `git status --porcelain=v2 -z` の結果を「ステージ済み」「変更」「未追跡」「競合」に分けて表示する。一覧の表示はフォルダごとのツリーとフラットな一覧を切り替えられる |
| 差分を開く | ファイルをクリックで差分タブ（仮タブ）を開く。ダブルクリックでファイル自体を開く |
| ステージ / ステージを外す | ファイルごと、セクション全体（`+` / `−`）、ハンク・行ごと（差分タブ） |
| 変更の破棄 | 確認のうえ `git restore`。未追跡のファイルの破棄は Windows のごみ箱へ移す（`git clean` は使わない） |
| .gitignore に追加 | ファイル名・拡張子・フォルダのどれで追加するかを選ぶ |

### 4.2 コミット

- コミットメッセージ欄で `Ctrl+Enter` を押すとコミットする。ステージ済みのものがないときは「すべての変更をステージしてコミットするか」を確認する（設定で「常にする」を選べる）。
- 1 行目が 72 文字を超えたら欄の中で知らせる（コミットは止めない）。
- 「コミット ▼」のメニュー: 「修正コミット」（`--amend`。プッシュ済みのコミットなら警告する）、「コミットしてプッシュ」、「サインオフ付きでコミット」。
- 書きかけのメッセージはリポジトリごとに保存し、次回起動時に戻す。直前のメッセージ 10 件を欄の履歴（`↑` / `↓`）から選べる。
- `user.name` / `user.email` が設定されていなければ、入力欄を出して、このリポジトリだけかすべてのリポジトリ（`--global`）に保存するかを選ばせる。
- コミットフック（`pre-commit` など）が失敗したら、その出力をダイアログで表示する。フックを飛ばす（`--no-verify`）ことはアプリからはしない。
- `commit.gpgsign` などの署名の設定はそのまま効く。パスフレーズの入力が必要な場合は、`git` が出すウィンドウ（pinentry など）に任せる。

### 4.3 ブランチとタグ

| 操作 | 仕様 |
| --- | --- |
| 一覧 | ローカルのブランチ、リモート追跡ブランチ（リモートごと）、タグを木構造で表示する。`feature/xxx` のような `/` 区切りはフォルダとして表示する。ローカルのブランチには上流との先行 / 遅れの数を出す |
| 切り替え | ブランチのダブルクリック、またはステータスバー・コマンドパレットの「ブランチの切り替え」（名前で絞り込む）。リモート追跡ブランチを選ぶと、同じ名前のローカルブランチを作って切り替える。作業ツリーの変更が切り替えを妨げるときは「スタッシュして切り替える / やめる」を選ばせる |
| 作成 | 現在のコミット、または履歴・ブランチ一覧で選んだものから作る。作ったあと切り替えるかを選べる |
| 名前変更 / 削除 | 削除はマージされていないブランチなら警告して確認する（`-D`）。リモートのブランチの削除（`git push --delete`）も確認のうえでできる |
| マージ | ブランチ一覧・リモートの表示・履歴の右クリックの「現在のブランチにマージ」、またはコマンドパレットの「ブランチをマージ」（名前で絞り込む）。ローカルのブランチ、リモート追跡ブランチ（`origin/main` など）、タグ、コミットのどれでもマージできる。実行前に、取り込まれるコミットの数と一覧を表示し、方法を選ばせる: 早送りできれば早送り（既定）/ 常にマージコミットを作る（`--no-ff`）/ 1 つのコミットにまとめる（`--squash`。コミットはメッセージ欄から行う）。作業ツリーに変更があってマージを妨げるときは「スタッシュしてマージ / やめる」を選ばせる。競合したら §4.8 |
| タグ | 作成（軽量 / 注釈付き）、削除、プッシュ |

### 4.4 履歴

- Git タブの「履歴」セクションに、選んだブランチ（既定は現在のブランチ。「すべてのブランチ」も選べる）のコミットを新しい順に表示する。ブランチの分かれと合流は左側の線（グラフ）で示す。
- 各行: メッセージの 1 行目、作者、日時（相対表示。ホバーで日時）、ブランチ名・タグ名の印。リモート追跡ブランチの位置（例: `origin/main`）も印で示すので、ローカルとリモートのずれが見える。
- 最初は 200 件を読み、スクロールで続きを読む。
- メッセージ・作者・ハッシュで絞り込める。
- コミットを選ぶと、変更したファイルの一覧と全文のメッセージを下に広げる。ファイルを選ぶと、そのコミットでの差分を差分タブで開く。
- 2 つのコミット（またはブランチ）を選んで「比較」すると、その間の差分の一覧を出す。
- コミットの右クリック: 「ハッシュをコピー」「ここからブランチを作る」「タグを付ける」「このコミットをチェックアウト」（デタッチ状態になることを確認する）「現在のブランチにマージ」「現在のブランチにチェリーピック」（§4.6）「このコミットを打ち消す（revert）」「この時点のファイルを見る」（コミット時点のファイルのツリーを読み取り専用で表示する）。
- `Ctrl` / `Shift` + クリックで複数のコミットを選べる（チェリーピックと比較に使う）。
- ファイルの履歴: そのファイルを変えたコミットだけを表示する（名前変更をたどる。`--follow`）。各コミットで「この時点の内容を開く」（読み取り専用のタブ）ができる。

### 4.5 リモート

#### リモートの表示

Git タブの「リモート」セクションで、リモートリポジトリの状態を見る。表示するのは最後にフェッチした時点の内容（リモート追跡ブランチ）で、表示のために通信はしない。

```text
▼ リモート
  ▼ origin   github.com/junmt/mark-shell   フェッチ: 10 分前  [⟳]
      main            ↓2  ← 現在のブランチの上流
      feature/git     ↓5 ↑0
      fix/typo        （ローカルなし）
  ▶ upstream ...
```

- リモートごとに URL、最後にフェッチした日時、フェッチのボタンを出す。
- その下にリモートのブランチを並べる。対応するローカルのブランチがあれば、ローカルにない（取り込んでいない）コミットの数 `↓` と、リモートにない（プッシュしていない）コミットの数 `↑` を出す。
- リモートのブランチを選ぶと、そのブランチの履歴を「履歴」セクション（§4.4）に表示する。現在のブランチにないコミットは強調する。コミットを選べば変更したファイルと差分を見られる。
- 「現在のブランチとの比較」で、現在のブランチにないコミット（取り込むもの）と、リモートのブランチにないコミット（送るもの）を 2 つに分けて一覧にし、両者のファイルの差分の一覧も出す。
- リモートのブランチの右クリック: 「フェッチ」（そのブランチだけ取得する）「チェックアウト」（同じ名前のローカルブランチを作る）「現在のブランチにマージ」「現在のブランチとの比較」「ここからブランチを作る」「名前をコピー」「リモートのブランチを削除」（確認する）。
- 「この時点のファイルを見る」で、リモートのブランチの最新のコミットのファイルのツリーを読み取り専用で表示し、ファイルを読み取り専用のタブで開ける（チェックアウトしなくても中身を確かめられる）。

#### リモートとのやり取り

| 操作 | 仕様 |
| --- | --- |
| フェッチ | `⟳` ボタン。既定ではすべてのリモートから取得し、削除されたリモートブランチを整理する（`--prune`）。`⟳` の右クリックや「リモート」セクションで、リモートを 1 つだけ、ブランチを 1 つだけ選んで取得することもできる。終わったら、取り込んでいないコミットの数を通知する。タグも取得する |
| プル | `↓` ボタン。上流のブランチから取り込む。方法（マージ / リベース / 早送りのみ）は `pull.rebase` などのユーザーの設定に従い、未設定なら早送りのみで行い、できなければ方法を選ばせる |
| プッシュ | `↑` ボタン。上流がなければ、リモートを選んで上流を設定する（`-u`）。拒否されたら（リモートが先に進んでいる）、プルするよう案内する |
| 強制プッシュ | `…` のメニューから。`--force-with-lease` だけを使い、確認のうえ実行する |
| 自動フェッチ | 既定で無効。有効にすると、ウィンドウが前面にあるときに指定の間隔（既定 5 分）でフェッチする |
| リモートの管理 | 一覧、追加、URL の変更、削除 |

- 実行中は Git タブの上部に進み具合（`git` が出す進捗）を表示し、取り消しボタンを出す。
- 通信中も他の操作（編集、別のファイルの差分を見るなど）はできる。同じリポジトリに対する Git の操作は 1 つずつ順に実行する。

### 4.6 チェリーピック

ほかのブランチ（ローカル・リモートを問わない）のコミットを選んで、現在のブランチに複製する。

- 履歴（§4.4）、リモートのブランチの履歴、比較の一覧で、コミットを 1 つまたは複数選び、右クリックの「現在のブランチにチェリーピック」で実行する。複数のときは古い順に適用する。
- 実行前に、対象のコミットの一覧と適用先のブランチを表示し、次を選ばせる。
  - コミットする（既定）/ 変更だけを取り込んでコミットしない（`--no-commit`。変更はステージ済みになり、メッセージ欄から自分でコミットする）
  - 元のコミットを記録する（`-x`。メッセージに `(cherry picked from commit ...)` を付ける）
- 現在のブランチにすでにあるコミット（同じ変更）は一覧で印を付け、既定では選ばない。
- マージコミットは親を選ばないと適用できないので、選んだときは親（`-m 1` など）を選ばせる。
- 作業ツリーに変更があって妨げるときは「スタッシュしてから実行 / やめる」を選ばせる。
- 競合したら、Git タブ上部に「チェリーピック中（2/5）」のように進み具合を表示し、§4.8 と同じ手順で解決する。解決後は「続ける」（`--continue`）、そのコミットだけ飛ばす「スキップ」（`--skip`）、全部取りやめる「中止」（`--abort`。確認する）を選ぶ。

### 4.7 スタッシュ

- 「スタッシュ」セクションに一覧を表示する。
- 作成（メッセージを付けられる。未追跡のファイルを含めるかを選ぶ）、適用、取り出し（`pop`）、削除、中身の差分表示。

### 4.8 競合の解決

- マージ・プル・チェリーピック・revert・スタッシュの適用で競合したら、Git タブ上部に「マージ中」「チェリーピック中」などと表示し、「競合」セクションに対象のファイルを並べる。
- 競合のあるファイルを開くと、エディタで `<<<<<<<` ～ `>>>>>>>` の部分を色分けし、その上に「現在の変更を採用」「取り込む変更を採用」「両方を採用」のボタンを出す。「競合」の一覧でファイルを選ぶと、現在の変更と取り込む変更の差分を差分タブで表示する。
- 印がなくなって保存したら、「解決済みにする」（`git add`）を押す。すべて解決したら「マージを完了」でコミットメッセージ欄に既定のメッセージを入れる（チェリーピックでは「続ける」。§4.6）。
- 「マージを中止」（`git merge --abort`）、「チェリーピックを中止」（`git cherry-pick --abort`）は確認のうえ実行する。
- アプリの外（ターミナルなど）で始めたマージやチェリーピックの途中でも、`.git` の状態から判断して同じ表示を出す。

## 5. 実行のしかた

- `git` は Rust 側（GitService）から子プロセスとして実行し、結果を JSON にして画面へ送る。画面から任意の `git` コマンドは実行できない（決まった操作だけを Tauri のコマンドとして用意する）。
- 機械が読む形式（`--porcelain=v2 -z`、`--format` に区切り文字を指定した `git log` など）を使い、表示言語に左右されないよう `LC_ALL=C` を付ける。ユーザーに見せるエラーは `git` の出力をそのまま添える。
- 認証の入力を `git` が端末に求めて止まらないよう `GIT_TERMINAL_PROMPT=0` で実行する。資格情報の入力は Git Credential Manager などの資格情報ヘルパーのウィンドウに任せる。それでも認証できないときは、「ターミナルで実行」ボタンで同じコマンドを内蔵ターミナルに入れて実行できるようにする（SSH の鍵のパスフレーズなど）。
- コンソールウィンドウが出ないように起動する（`CREATE_NO_WINDOW`）。
- 状態の更新: ファイルの変更の監視（[functional-spec.md](functional-spec.md) §6）で作業ツリーか `.git` の中（`HEAD`、`index`、`refs/` など）の変化を検出したら、300ms 待ってから `git status` を実行し直す。リポジトリの最上位がルートディレクトリの外にあるときは、その `.git` も監視する。ウィンドウが前面に戻ったときにも更新する。
- 大きなリポジトリ: 未追跡のファイルが 5,000 件を超えたら一覧の表示を打ち切り、`.gitignore` の見直しを案内する。`git status` が 5 秒を超えるときは自動の更新を止め、手動の更新ボタンを出す。
- 内蔵ターミナルや AI ツールが `git` を実行した場合も、`.git` の変化として検出して表示を更新する。

### 5.1 WSL のフォルダ

`\\wsl.localhost\...` のフォルダでは、WSL の中のエージェント（[architecture.md](architecture.md) §2.2）が WSL の `git` を実行する。Windows 側の `git` は使わない（改行コードの扱いやファイルの実行権限が食い違うため）。WSL に `git` がなければ、§2 の「`git` が見つからない」と同じ案内を出す。

## 6. 設定

| 項目 | 既定 |
| --- | --- |
| Git 連携を使う | 有効 |
| `git` の場所 | 自動（PATH から探す） |
| 自動フェッチ | 無効（有効時の間隔 5 分） |
| ステージ済みがないときのコミット | 確認する |
| 差分の表示モード | 左右 |
| エディタの変更の帯 | 表示する |
| ファイルツリーの状態の色 | 表示する |

## 7. 対象外（初期バージョン）

- クローン（`git clone`。ターミナルから実行してそのフォルダを開く）
- リベース、対話的リベース、`reset` によるブランチの巻き戻し
- サブモジュールの追加・更新、Git LFS の操作（LFS で管理されたファイルの表示は `git` に任せる）
- `git blame` の表示
- GitHub などのホスティングサービスとの連携（プルリクエストの作成・表示など）
- AI によるコミットメッセージの作成（AI はターミナルから使う。[terminal-ai.md](terminal-ai.md)）
