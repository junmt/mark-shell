# ターミナルと AI 連携の仕様

## 1. 方針

- AI モデルや API クライアントはアプリに組み込まない。PC にインストール済みの AI ツールを、内蔵ターミナルからそのまま動かす。
- アプリが用意するのは「ルートディレクトリで開いたシェル」「AI ツールの検出とワンクリック起動」「AI が書き換えたファイルの即時反映」の 3 つ。
- 認証、課金、モデルの選択は各 AI ツールの仕組みに任せる。アプリは API キーなどを預からない。

## 2. ターミナル

### 2.1 基本機能

- 右ペインの下部に表示する。`` Ctrl+` `` で表示を切り替える。
- タブで複数のシェルを開ける。タブは左右・上下に分割できる。
- ConPTY を使うので、色・カーソル移動・全画面の TUI（Claude Code の対話画面など）が正しく表示される。
- 日本語の入出力（UTF-8）と全角文字の幅に対応する。シェル起動時にコードページを UTF-8（65001）にする。
- コピー＆ペースト（選択で自動コピーは設定で切り替え）、URL のクリック、スクロールバック 10,000 行、検索。
- 履歴があるときはスクロールバーを常に表示する（Claude Code などの全画面のツールのように履歴がない画面では出さない）。
- ターミナルの一覧は左ペインの下側（ファイルツリーの下）に縦に並べ、ターミナル本体は右ペインの下側に出す。一覧の各行には状態（処理中は点滅する点、待機中は小さな点、終了は輪）とシェルや AI ツールの名前を出す。AI ツールの行には、ツールがターミナルに付けたタイトル（Claude Code なら会話の題名）も 2 行目に出す。処理中かどうかは、タイトルのスピナー（Claude Code は処理中に点字のスピナーを付ける）と、出力が続いているかで判断する。
- フォントとサイズはエディタと別に設定できる。Nerd Font を推奨する。

### 2.2 シェルの種類

起動時に PC 上のシェルを検出し、使えるものだけを一覧に出す。

| シェル | 検出方法 |
| --- | --- |
| PowerShell 7 | `pwsh.exe` が PATH にある |
| Windows PowerShell 5.1 | `%SystemRoot%\System32\WindowsPowerShell\v1.0\powershell.exe` |
| コマンドプロンプト | `%ComSpec%` |
| Git Bash | `Git for Windows` のインストール先の `bin\bash.exe` |
| WSL | `wsl.exe -l -q` でディストリビューションを列挙 |

- 既定のシェルは設定で選ぶ（初期値: PowerShell 7 があればそれ、なければ Windows PowerShell）。
- カスタムシェル（任意の実行ファイルと引数）も登録できる。

### 2.3 作業ディレクトリと環境変数

- 新しいシェルの作業ディレクトリは、設定で次から選ぶ（初期値: ルートディレクトリのルート）。
  - ルートディレクトリのルート
  - 開いているファイルのあるフォルダ
- WSL のシェルには、Windows のフォルダなら `/mnt/<ドライブ>/...`、WSL のフォルダなら Linux のパス（`/home/...`）で作業ディレクトリを渡す（§2.4）。
- シェルに次の環境変数を渡し、スクリプトや AI ツールから参照できるようにする。

| 変数 | 内容 |
| --- | --- |
| `MARKSHELL_ROOT` | ルートディレクトリの絶対パス（WSL のフォルダを WSL の中で使うときは Linux のパス） |
| `MARKSHELL_NOTE` | 起動時に開いていたファイルの絶対パス（同上） |
| `MARKSHELL_SELECTION_FILE` | 起動時のエディタの選択範囲を書き出した一時ファイルのパス（選択がない場合は未設定） |
| `MARKSHELL_CONTEXT_FILE` | いま開いているファイルと選択範囲を書いた JSON ファイルのパス。起動後もタブの切り替えや選択の変更に合わせて書き換わる（§3.4） |

### 2.4 WSL のフォルダ

`\\wsl.localhost\<ディストリビューション>\...` のフォルダを開いたときは、VS Code の WSL 拡張と同じく WSL の中で作業する（仕組みは [architecture.md](architecture.md) §2.2）。

- 新しいターミナルは、シェルを指定しなければそのディストリビューションのシェルで、開いているフォルダの Linux のパスで始まる。メニューから PowerShell などを選ぶこともできる。
- CLI の AI ツール（Claude Code など）は、WSL の中にインストールされたものを WSL の中で起動する。ログインシェルの PATH で探すので、`~/.local/bin` などに入れたものも見つかる。ツールが終わるとそのディストリビューションのシェルが残る。
- Claude Code に開いているファイルを伝える仕組み（§3.4）も WSL の中で動く。ファイルのパスは Linux のパスで伝える。
- WSL の中の AI ツールが書き換えたファイルは、WSL の中で変更を監視してすぐに画面に反映する。
- ステータスバーに「WSL: <ディストリビューション>」と Linux のパスを表示する。
- ファイルの削除は Linux のごみ箱（`~/.local/share/Trash`）に移す。

## 3. AI ツール連携

### 3.1 AI ツールの検出

起動時と設定画面を開いたときに、登録済みの AI ツール定義をもとに PC を調べる。PATH（`where.exe` 相当）と既知のインストール先を探す。

初期状態で定義を同梱するツール:

| ツール | 種類 | 検出するコマンド | 起動時の動作 |
| --- | --- | --- | --- |
| Claude Code | CLI | `claude` | ターミナルの新しいタブで `claude` を実行 |
| Gemini CLI | CLI | `gemini` | ターミナルの新しいタブで `gemini` を実行 |
| Codex CLI | CLI | `codex` | ターミナルの新しいタブで `codex` を実行 |
| Antigravity | IDE | `antigravity`（またはインストール先の実行ファイル） | ルートディレクトリを Antigravity で開く |

- 見つかったツールだけをツールバーの「AI ▼」メニューとコマンドパレットに出す。
- 見つからないツールは設定画面に「未インストール」と表示し、公式のインストール手順へのリンクを出す（クリックしたときだけブラウザで開く）。
- 各ツールのコマンド名・場所・起動方法は変わる可能性があるため、定義はアプリ本体のコードに埋め込まず、データファイルとして持ち、ユーザーが上書き・追加できるようにする。

### 3.2 AI ツール定義

`%APPDATA%\mark-shell\ai-tools.json` に保存する。ユーザーが任意のツールを追加できる。

```json
{
  "tools": [
    {
      "id": "claude-code",
      "name": "Claude Code",
      "kind": "cli",
      "detect": { "command": "claude" },
      "launch": {
        "shell": "default",
        "command": "claude",
        "args": [],
        "cwd": "${root}"
      },
      "actions": [
        {
          "id": "ask-about-note",
          "label": "このファイルについて聞く",
          "args": ["${noteRelativePath} を読んで、要点をまとめてください"]
        }
      ]
    },
    {
      "id": "antigravity",
      "name": "Antigravity",
      "kind": "ide",
      "detect": { "command": "antigravity" },
      "launch": { "command": "antigravity", "args": ["${root}"], "detached": true }
    }
  ]
}
```

- 使える置換変数: `${root}`（ルートディレクトリ）、`${note}`（開いているファイルの絶対パス）、`${noteRelativePath}`（ルートディレクトリからの相対パス）、`${noteDir}`、`${selectionFile}`、`${claudeSettings}`（Claude Code の `--settings` に渡すフック定義ファイル。§3.4）。
- `kind: "cli"` はターミナルのタブで実行し、`kind: "ide"`（`detached: true`）は別ウィンドウのアプリとして起動する。
- 引数はシェルの文字列連結ではなく引数配列として渡し、ファイル名などによるコマンドインジェクションを防ぐ。

### 3.3 エディタからの呼び出し

- エディタの右クリックメニューとコマンドパレットに「AI で開く」を置き、定義済みの `actions` を選べるようにする。
- 選択範囲がある場合は `${selectionFile}` に書き出してから起動する。
- 起動した AI セッションのタブには、ツール名と対象ファイル名を表示する。

### 3.4 開いているファイルを前提にした会話

- Claude Code には、いま開いているファイルと選択範囲を質問のたびに伝える。「このファイルを要約して」「ここを直して」のように、パスを書かずに話せるようにするため。
- アプリは開いているファイルと選択範囲（10,000 文字まで）を `%LOCALAPPDATA%\mark-shell\tmp\context-<プロセス ID>.json` に書き、タブの切り替えや選択の変更のたびに書き換える。終了時に消す。
- Claude Code（定義の id が `claude-code`）は `--settings <フック定義ファイル>` 付きで起動する。定義の引数に `--settings` がなければアプリが自動で足す。id が違う定義で使うときは引数に `"--settings", "${claudeSettings}"` を書く。このファイル（`%LOCALAPPDATA%\mark-shell\claude-settings.json`）には UserPromptSubmit フックとして `mark-shell.exe --ai-context` を登録してある。フックは `MARKSHELL_CONTEXT_FILE` の内容を文章にして標準出力に出し、Claude Code がそれを質問に添える。
- フックはシェルを通さずに実行ファイルを直接起動する（exec 形式）。Git Bash の有無や PowerShell の文字コードに左右されない。
- `--settings` で渡したフックは、ユーザー自身の Claude Code の設定に追加される（置き換えない）。
- ターミナルで手で `claude` を起動した場合は伝わらない。`claude --settings "$env:LOCALAPPDATA\mark-shell\claude-settings.json"` と起動すれば同じになる。

### 3.5 AI による変更の反映

- AI ツールがルートディレクトリ内のファイルを作成・変更・削除すると、ファイル監視で検出して即座に左ペインのファイルツリー、エディタ、プレビューに反映する（[functional-spec.md](functional-spec.md) §6 と同じ処理）。
- 直近に AI セッションが動いている間に変わったファイルは、左ペインのツリーに「変更あり」の印を付け、変更前との差分を表示できるようにする（差分の元データは、開いていたファイルについてアプリがメモリ上に持っている変更前の内容。ルートディレクトリが Git リポジトリの場合は Git の差分も表示できる）。
- 変更を取り消すボタン（変更前の内容に戻す）を用意する。

### 3.6 AI 向けの説明ファイル

- 設定で有効にすると、ルートディレクトリ直下に AI ツール向けの説明ファイル（Claude Code なら `CLAUDE.md`、他ツールは `AGENTS.md` など各ツールが読む名前）のひな形を作る。
- ひな形には、フォルダ構成、ファイル名の規則、フロントマターの形式、`[[内部リンク]]` の書き方、`assets/` の使い方を書く。AI がこのディレクトリの書式を守って編集できるようにするため。
- 既にファイルがある場合は上書きしない。

## 4. オフライン時の動作

- シェルの起動、AI ツールの検出と起動は、ネットワークがなくてもアプリとして行う。
- AI ツール自体がネットワークを必要とする場合、そのエラーはツールがターミナルに表示する。アプリはステータスバーにオフラインであることを表示するだけで、起動を止めない。
- ローカルで動く AI（Ollama などの CLI）を定義に追加すれば、オフラインでも AI を使える。

## 5. セキュリティ

- シェルは通常のユーザー権限で起動し、管理者権限への昇格はしない。
- AI ツールがアクセスできる範囲はツール側の権限設定に従う。アプリは作業ディレクトリをルートディレクトリにすることで、意図した範囲で作業させやすくする。
- `ai-tools.json` はルートディレクトリではなく `%APPDATA%` に置く。ルートディレクトリ内のファイル（他人から受け取ったフォルダや、同期・Git で届いたファイル）によって任意のコマンドが実行されることを防ぐため。
